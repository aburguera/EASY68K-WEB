INTERRUPTS

        
        
Checked (default): every run starts with SR's interrupt-priority mask at 000 — every IRQ level is admitted immediately, matching the real original EASy68K's own out-of-box behavior. Unchecked: starts at 111, matching real 68000 hardware reset behavior (IRQ1-6 stay blocked until the program itself lowers the mask; IRQ7 is always non-maskable either way). Takes effect on the next Assemble or Reset.

What this is

    
This is a browser port of EASy68K — a 68000 assembler, simulator, and IDE — built from the real original C++ source, compiled to run in your browser. Nothing you do here is ever uploaded anywhere; the assembler, the simulator, and every file you work with all run entirely on your own machine, inside this page.


    
Top bar: panel visibility

    
The bar along the very top (with the "EASy68K // WEB" brand and the engine/status indicators) has three panel-visibility toggles, right before those indicators: they hide/show the left (Explorer), right (Registers/Memory/Stack), and bottom (Messages) panels — each icon shows which panel it controls (a small rectangle with that side highlighted) and dims once that panel is hidden. Hiding a panel lets the editor expand to fill the freed space — handy on a small screen (a laptop) where you want to focus on just the code for a while. Every hidden panel can always be brought back with the same button; these buttons live in the top bar specifically (not inside the panels themselves) so they stay reachable even while their panel is hidden. Which panels are visible is remembered across reloads.

    
A separate 🌙/☀️ theme toggle (dark by default; your choice is remembered too) lives in the editor's own toolbar, next to the search box and the Settings/Help icons.


    
The two modes: Editing and Simulating

    
The app is always in one of two modes, shown by the badge next to the "Editor" title:

    
    
      
  • EDITING — write and manage source files. The toolbar's last group is labeled ASSEMBLE; only its Assemble button is active.
    • 
      
  • SIMULATING — after a successful Assemble, the view switches to a read-only listing of your program (source and machine code merged, matching the real assembler's .L68 listing) and the same toolbar group relabels to SIMULATE, enabling Run, Step, Step Over, and Reset. The editor itself becomes read-only while simulating (🔒 shown in the title bar) — press Reset to return to editing.
    • 
    

    
ℹ️
Breakpoints only exist during simulation. Click a line number in the listing to toggle one; Run stops when the PC reaches it. They're cleared every time you Reset, so a breakpoint never ends up pointing at the wrong line after you've since edited the file.

To the right of the groups: a search box (Enter to find/advance), Editor settings (font, size, tab width, column mark), and this Help button.

    
A thin amber column-mark line runs down the editor at a fixed column (80 by default) - a visual guide only, it has no effect on assembling. Its column is editable in Settings. A status bar along the bottom of the editor shows the cursor's current line and column (Ln, Col), updated as you type, click, or move the caret with the keyboard.


    
Files panel & the virtual file system

    
The left-hand Files tab is a small file tree with its own right-click context menu (New File/Folder, Upload files/ZIP, Rename, Cut, Copy, Paste, Delete) and drag-and-drop for moving or copying entries between folders. Files can also be dragged in directly from your desktop.

    
⚠️

      Nothing here is ever linked to your real disk. Import Folder, Upload files, and Import ZIP all just copy files into the browser — they're auto-saved locally (IndexedDB) and survive closing the tab or reloading the page, but editing them here never changes your real files, on any browser, and nothing you import is ever sent anywhere. To get a real copy back out, use Export ZIP or Download file — an explicit, one-time download, not an ongoing link.


      This storage is private to this one browser (not synced across browsers, devices, or even a regular vs. private/incognito window in the same browser), and it can be erased not only by this app's own 🗑 Clear Browser Storage button (which is permanent and cannot be undone) but also by clearing site data/cookies for this page from your browser's own settings. If a project matters, keep a real copy on disk via Export ZIP — don't rely on browser storage as your only copy.
    


    
Registers, Memory & Stack (right column)

    
    
      
  • Registers — D0-D7, A0-A7, PC, SR, USP, SSP, and the individual SR flag/interrupt-mask bits. Values are editable directly (click and type) while simulating.
    • 
      
  • Memory — a scrollable hex/ASCII dump. Jump to an address, or straight to PC/USP/SSP/A7. Click a byte to start "type-through" editing (2 hex digits, or 1 ASCII character, auto-advancing to the next byte) — an invalid entry briefly flashes red and reverts rather than silently failing.
    • 
      
  • Stack — three independent stack views at once, each pointed at any address register or at the User/Supervisor stack pointer specifically.
    • 
    


    
Output window

    
Opened with the Output button (right toolbar). This is where your program's TRAP #15 graphics and text output actually draws, at whatever resolution the program requests (640×480 by default). It's a real floating window: draggable, resizable, and independently maximizable to fullscreen (Esc, or its own restore button, to exit) — Reset to actual size snaps it back to exact 1:1 pixel scale.


    
Hardware & Interrupt window

    
Opened with the Hardware button. The Hardware tab shows the memory-mapped 7-segment display, LEDs, toggle switches, and push buttons a program can read/write like real peripherals — each device's mapped address is editable (with a one-click reset to its default). The Interrupt tab lets you fire IRQ levels 1-7 by hand, including an auto-repeat timer per level, to test a program's own interrupt handlers without needing real hardware.

    
ℹ️
An interrupt only actually fires if its level is above SR's current interrupt-priority mask (real 68000 behavior, not a bug) — a masked IRQ button press is logged as masked rather than silently doing nothing.


    
Settings

    
The gear icon opens editor font/size/tab-width/column-mark preferences and one simulator option: which interrupt mask a run starts with (EASy68K's own convention of starting fully open, vs. real 68000 hardware's fully-masked reset state).


    
ℹ️
This guide covers this web port's own interface — its panels, buttons, and windows. It does not teach the Motorola 68000 instruction set, assembly-language programming in general, or every assembler directive. For that, and for anything about EASy68K itself this guide doesn't go into, see EASy68K's own official documentation at easy68k.com.

  

  

      
D0.B selects the task. This is the real TRAP #15 dispatch logic from the original EASy68K sources. Text and graphics draw to the same screen, exactly like real EASy68K (text is drawn as glyphs onto the graphics canvas by row/col). Only serial (40-43) and network (100+) are unimplemented, by explicit choice.

        Task 32 is a single dispatch point for several unrelated hardware/environment sub-functions, real EASy68K's own convention for it (not specific to this port). The ".Y" in "32.Y" below is not a .B/.W/.L operand-size suffix - it means "load D1.B with the sub-function number Y before the TRAP #15", exactly like choosing which task number to put in D0.B in the first place, just one level down. Every sub-function that returns a value overwrites that same D1 (as a full D1.L) with its result, right after D1.B was read as the selector - so D1 is used as input then immediately as output, not two different registers.

NETWORK / SERIAL (unimplemented, by choice)

      
Serial (40-43) and networking (100-107) log a one-time explanation and report a definite failure code, so a program checking the result can detect it and continue gracefully.

      
WEB PORT EXTENSIONS (200-255 reserved)

      
Tasks 200-255 are reserved exclusively for this web port's own debugging/convenience additions, so they can never collide with a genuine task number the real EASy68K might add.

      
Tasks 200/201/203/206/213/214/215/217/220 are the CONSOLE_LOG family: exact replicas of the real text-printing tasks 0/1/3/6/13/14/15/17/20 above (same task number + 200), except they write to the Log panel (in the same distinctive amber color) instead of the screen/output window. The real tasks 0/1/3/6/13/14/15/17/20 themselves are completely unaffected.
